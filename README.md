# Projects HQ

Личная админ-панель для всех проектов: здоровье продакшенов, оплата VPS-серверов, счета заказчиков и уведомления в Telegram — в одном месте.

## Что умеет

- **Мониторинг проектов.** Каждые 5 минут (настраивается) воркер опрашивает адрес продакшена или отдельный health-check URL, сохраняет время ответа и HTTP-код, считает аптайм за 24 часа и 7 дней, читает срок действия SSL-сертификата. Есть кнопки «Проверить сейчас» и «Проверить все проекты».
- **Пилоты.** У проекта можно указать срок пилота с клиентом (начало и окончание) и решение клиента: «продолжаем» или «отказ». Статус пилота виден в списке и карточке проекта. За 7 дней до окончания пилот попадает в «Требует внимания», бот напоминает за 7, 3, 1 день и в последний день, а если срок прошёл без отмеченного решения — присылает одно напоминание и держит критичный алерт, пока решение не отмечено.
- **Серверы и оплата VPS.** Для каждого сервера хранятся провайдер, хост, конфигурация, стоимость, период (месяц/квартал/год) и дата «оплачен до». Кнопка «Оплатить» записывает платёж и продлевает срок; история оплат сохраняется. За 7 дней до конца оплаченного периода сервер попадает в раздел «Требует внимания», после — считается просроченным.
- **Клиенты и счета.** Счета с суммой, сроком и статусом (черновик / выставлен / оплачен / отменён). Панель показывает сумму к получению, просроченные счета и что получено за 30 дней. Клиента со счетами удалить нельзя. Для проекта с клиентом и ежемесячной платой можно включить **автоматические счета**: каждый месяц в выбранный день (1–28) воркер выставляет счёт на абонплату со сроком оплаты `INVOICE_DUE_DAYS` дней и сообщает об этом в Telegram; повторно за тот же месяц счёт не создаётся.
- **Домены.** Домены с регистратором, проектом, стоимостью продления и датой окончания. Для зон с RDAP (`.help`, `.com` и др.) срок подтягивается автоматически раз в сутки; для `.kz` — оценка по дате регистрации из WHOIS (ближайшая годовщина), ручную дату она не перезаписывает. Домен за 30 дней до окончания попадает в «Требует внимания».
- **Обзор.** Плитки с ключевыми числами, список «Требует внимания» (недоступные проекты, истекающие сертификаты, сроки оплаты серверов, просроченные счета), таблица доступности, ближайшие оплаты и открытые счета.
- **Аналитика.** Раздел с графиками (`GET /api/dashboard/analytics`). «Здоровье»: общий аптайм по дням за 14 дней, карта доступности «проект × день», среднее время ответа, запас SSL-сертификатов, проекты по стадиям. «Финансы»: поступления и оплаты серверов по месяцам за год, структура расходов на серверы, запас оплаты, прогноз продлений на полгода, долги клиентов. Все суммы — в тенге (KZT, ₸).
- **Telegram.** При падении и восстановлении проекта приходит сообщение; каждое утро — сводка по алертам (если есть что сообщать). Отдельные **напоминания о платежах** приходят один раз на каждый порог: оплата сервера — за 7, 3, 1 день и в день оплаты; продление домена — за 30, 7, 1 день и в день окончания; ожидаемая оплата от клиента по счёту — за 3, 1 день и в день срока; при просрочке — одно сообщение. Напоминания и автосчета отправляются только в течение 12 часов после `DAILY_DIGEST_HOUR_UTC`, ночью бот молчит.
- **GitHub.** Для проектов с ссылкой на репозиторий подтягиваются дата последнего push и число открытых issues (нужен токен для приватных репозиториев).
- **Закрытая регистрация.** Первый созданный аккаунт становится администратором, после этого регистрация закрывается; дополнительные аккаунты разрешаются через `ADMIN_EMAILS`.

Интерфейс на русском языке. Панель работает в тенге: новые суммы всегда сохраняются в KZT и показываются со знаком ₸; суммы в других валютах (если они появятся в данных) никогда не конвертируются и в аналитику не попадают.

## Стек

Bun · Hono · Prisma 7 · PostgreSQL 18 · React 19 · Vite · TanStack Router/Query/Form · shadcn/ui · общие Zod-контракты в `packages/contracts`.

## Быстрый старт локально

Нужны Bun и Docker (для PostgreSQL 18, он обязателен из-за `uuidv7()` в схеме).

```bash
bun install
docker compose up -d postgres
cp backend/.env.example backend/.env
bun run --cwd backend prisma:migrate
```

Запустите поверхности в отдельных терминалах:

```bash
bun run dev:backend   # API на http://localhost:3000
bun run dev:worker    # фоновые проверки, GitHub-синхронизация, дайджест
bun run dev:web       # панель на http://localhost:5173
```

Откройте панель и создайте первый аккаунт — он станет администратором. Чтобы сразу получить список проектов из GitHub-аккаунта владельца (имена, ссылки на репозитории, ориентировочные статусы), выполните:

```bash
bun run seed
```

Сид идемпотентен: уже существующие проекты (по slug) не трогает.

## Деплой на VPS

Панель рассчитана на один из ваших серверов: `deploy/docker-compose.prod.yml` поднимает PostgreSQL, API, воркер и Caddy, который раздаёт фронтенд и выпускает HTTPS-сертификат автоматически.

```bash
git clone https://github.com/Mastife/vibe projects-hq && cd projects-hq
cp deploy/.env.production.example deploy/.env.production   # заполните домен, пароли, Telegram
docker compose -f deploy/docker-compose.prod.yml --env-file deploy/.env.production up -d --build
```

Подробный runbook, обновление и вариант с DigitalOcean App Platform — в [docs/DEPLOYMENT.md](docs/DEPLOYMENT.md).

## Настройки

Все переменные описаны в `backend/.env.example`. Ключевые:

| Переменная | Назначение |
| --- | --- |
| `ADMIN_EMAILS` | Email-адреса, которым разрешена регистрация после первого аккаунта |
| `APP_URL` | Публичный адрес панели для ссылок в уведомлениях |
| `HEALTH_CHECK_INTERVAL_SECONDS` | Период проверок доступности (по умолчанию 300) |
| `HEALTH_CHECK_TIMEOUT_MS` | Таймаут одной проверки (по умолчанию 10000) |
| `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID` | Уведомления о падениях и ежедневная сводка |
| `DAILY_DIGEST_HOUR_UTC` | Час сводки в UTC (6 = 09:00 по Москве) |
| `INVOICE_DUE_DAYS` | Срок оплаты автоматических счетов в днях (по умолчанию 10) |
| `GITHUB_TOKEN` | Токен для приватных репозиториев (scope `repo`) |

## Структура репозитория

- `backend` — Bun + Hono + Prisma: API (`src/index.ts`), воркер-планировщик (`src/worker.ts`), разовые задачи (`src/cron.ts`), доменные модули `projects`, `servers`, `clients`, `invoices`, `dashboard`, `health`, `notifications`, `github`.
- `web` — React-панель: `src/pages` (обзор, проекты, серверы, клиенты, счета), `src/components` (формы, таблицы, бейджи статусов), `src/lib` (API-клиент, хуки TanStack Query, форматирование).
- `packages/contracts` — Zod-схемы запросов, ответов и ошибок, общие для бэкенда и фронтенда.
- `deploy` — production-стек для VPS (Compose, Caddyfile, пример env).
- `.do` + `scripts/prepare-do-specs.mjs` — альтернативный путь деплоя в DigitalOcean App Platform.
- `docs` — архитектура, тестирование, деплой, локальная база, хранилище файлов.

## Команды

```bash
bun run dev:backend | dev:worker | dev:web
bun run typecheck                 # все воркспейсы
bun run test                      # deploy-скрипты, контракты, backend (unit + integration), web
bun run test:backend:integration  # API-тесты через Docker PostgreSQL
bun run e2e:web                   # Playwright: путь администратора от регистрации до оплаты сервера
bun run --cwd web lint
bun run --cwd backend start:cron -- health:check   # разовые задачи: health:check, health:prune, github:sync, digest:daily, domains:sync, billing:auto, reminders:send
bun run smoke:backend:docker      # сборка и запуск backend-образа
bun run deploy:do:specs           # спецификации DigitalOcean в .scratch/deploy
```

## Как это устроено

API: `маршрут → Zod-валидация → guard сессии → сервис → Prisma → DTO`. Все маршруты панели закрыты bearer-токеном; refresh-токен живёт в HttpOnly-cookie. Воркер использует те же сервисы, что и API, и запускается из того же Docker-образа. Подробнее — [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md), правила тестирования — [docs/TESTING.md](docs/TESTING.md), инструкции для агентов — [AGENTS.md](AGENTS.md) и [CLAUDE.md](CLAUDE.md).

Репозиторий вырос из шаблона vibe (этот же репозиторий, форк шаблона): его первичные инструкции по установке удалены как выполненные, а панель живёт здесь.
